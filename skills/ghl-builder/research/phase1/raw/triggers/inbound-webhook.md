## Mandatory test → map → save flow

1. Copy the generated URL from the panel.
2. POST a real JSON request to it. Captured sanitized equivalent:

   ```bash
   curl -X POST '<generated-url>' \
     -H 'content-type: application/json' \
     -d '{"event":"zzz-spike-sample","contact":{"email":"sample@example.invalid"},"amount":42}'
   ```

3. Click **Fetch sample requests**, select the timestamped request, and use it as the mapping reference.
4. Click **Save trigger**. GHL automatically inserts a required **Create update contact** action for this contactless trigger.
5. Map at least Email or Phone in that action. Captured: Email = `{{inboundWebhookRequest.contact.email}}`.
6. Click **Save action**, then the top-bar **Save**.

Without steps 2–3, the panel reports `A Mapping Reference is required for an Inbound Webhook Trigger`. Without step 5, the auto-created action reports that Email or Phone is required and blocks the workflow save.

## Location-data-dependent fields

None. The URL is location-scoped but generated by this trigger, not selected from a location-data catalog.

## Quirks

- The mandatory mapping reference is not returned by the trigger read endpoint; it is bound server-side to the generated trigger/webhook ID.
- Clicking panel **Cancel** opens a special confirmation that would delete the trigger, test requests, and URL. Safe exit is **Save trigger** → save the required action → top-bar **Save**.
- The trigger is premium. It was saved in Draft and never published.
