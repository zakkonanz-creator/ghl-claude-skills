## API facts (Phase 0, proven)
- Internal builder API host: `backend.leadconnectorhq.com`. Headers: `authorization: Bearer <sniffed>`, `source: WEB_USER`, `channel: APP`. CORS-locked to the builder iframe origin → run fetches INSIDE the builder iframe (`frame.evaluate(fetch...)`) or read via response interception.
- `POST /workflow/{loc}` create · `POST /workflow/{loc}/trigger` create trigger · `PUT /workflow/{loc}/{id}` saves the FULL doc (partial body → HTTP 422; always GET → modify → PUT whole doc).
- `GET /workflow/{loc}/{id}?includeScheduledPauseInfo=true` → detail incl. `fileUrl` (Firebase steps JSON, curl-able, no auth). `GET /workflow/{loc}/trigger?workflowId={id}` → triggers.
- Trigger `active` flag = publish state. Draft ⇒ always `active:false`; publishing (status:"published" in the PUT) flips it. No separate activate call.
- Tags are referenced by NAME in action attributes, not id. `POST /locations/{loc}/tags` works for fixture creation.
